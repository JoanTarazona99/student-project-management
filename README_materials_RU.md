# Материалы и проверка — локальный учебный блок

Не изменяет SQL-схему и существующие модули, кроме подключения router в main.py.

Установка (Git Bash, активная .venv):

    python -m pip install python-multipart
    python -m scripts.register_materials_router
    python -m pip freeze > requirements.lock.txt
    python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

Эндпоинты:
- POST /stages/{stage_id}/materials — студент проекта, multipart file.
- GET /stages/{stage_id}/materials — история версий и решений, limit/offset.
- GET /materials/{material_id}/download — скачивание после проверки доступа.
- POST /materials/{material_id}/review — назначенный руководитель/преподаватель.
- GET /notifications — только собственные уведомления, unread_only/limit/offset.
- PATCH /notifications/{notification_id}/read — отметить собственное уведомление.

Правила:
- TXT UTF-8, PDF, DOCX; не более 20 МиБ на файл, пустые файлы запрещены.
- Имя хранения генерируется сервером; uploads не публикуется как статика.
- Проверки содержимого поверхностные, не антивирус и не гарантия безопасности.
- Повторная загрузка разрешена после возврата на доработку.
- Проверяется только последняя непроверенная версия; старые версии сохраняются.
- Для revision обязательны непустые remarks.
- accepted завершает этап и открывает следующий. Даты являются плановыми:
  наступления starts_at ждать не требуется; порядок этапов соблюдается.
- Решения записываются по одному на версию. Перепроверка: 409.
- Журнал событий: public.audit_events, без содержимого файлов.

Ограничения учебного локального режима:
- FastAPI разбирает multipart до вызова обработчика. Лимит 20 МиБ проверяется
  при копировании файла, а не до разбора тела HTTP. Перед публикацией требуется
  внешний лимит тела запроса, ограничения частоты и общего объема хранилища.
- Между файловой системой и PostgreSQL нет общей атомарной транзакции.
  После ошибки БД или аварии могут остаться файлы без записи (orphan files).
  Если результат commit неизвестен, файл намеренно сохраняется. Автоматическая
  очистка orphan files в этот блок не входит. Не удаляйте uploads целиком:
  успешные записи БД ссылаются на файлы в этой папке.
- Резервная копия должна включать как БД, так и uploads.
- Интеграция с реальным PostgreSQL требует проверки на вашем компьютере.
  Воспроизводимые изолированные проверки и CI описаны в [README_tests_RU.md](README_tests_RU.md).
