# Минимальный web-интерфейс: доступ и просмотр

Первая версия интерфейса, не полный frontend системы. HTML, локальный CSS,
JavaScript без framework, CDN, внешних шрифтов или сборки. Ресурсы расположены
в `app/ui/`; FastAPI предоставляет только `/ui`, `/ui/` и два явно указанных
ресурса `/ui/assets/app.js`, `/ui/assets/style.css`.
Корень, `/health`, `/docs` и JSON API не меняются.
Каталоги репозитория, `.env`, backups, database и uploads не публикуются.

## Запуск и вход

Используйте существующую конфигурацию backend и виртуальное окружение.
Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/ui`. Пользователь вводит email и пароль уже
существующего аккаунта; демонстрационные учетные данные не встроены.
Новых пользователей автоматически не создается.
Используются `POST /auth/login` и `GET /auth/me`, штатные JWT и проверки БД.
Пароль очищается в поле сразу после отправки и не сохраняется приложением,
не выводится в сообщения/консоль. Настройки сохранения паролей самим браузером
оператор выбирает отдельно.

JWT находится только в переменной JavaScript в памяти этой страницы:
без localStorage, sessionStorage, cookies, query string или внешних ресурсов.
Перезагрузка страницы требует нового входа. «Выйти» удаляет токен и
отображаемые данные локально, **не отзывает JWT на сервере**.
Нет refresh tokens, восстановления сессии или автоматического обновления JWT.

Запросы централизованы и используют Authorization только для текущего токена.
Смена раздела/сессии отменяет запросы через AbortController и изменяет номер
поколения; даже поздний уже полученный ответ прошлой сессии не возвращает данные.
При 401 очищаются данные/сессия и выводится объяснение нового входа.
При 403 выводится отказ, без повторения запрещенного действия; дополнительно
читается /auth/me для обновления меню. 404 скрывает недоступный ресурс,
409/422 дают безопасные русские сообщения; ошибки сети/сервиса допускают повтор.
Сообщения исключений и токены не печатаются.

## Разделы и права

Меню построено по эффективным permissions из /auth/me. «Обновить права»
перечитывает identity/permissions и очищает текущую страницу данных.
Скрытие кнопок не заменяет серверную авторизацию; все данные приходят
из существующих защищенных endpoints.

- **Проекты** (`projects.read`): список limit/offset по 10 записей, ID темы
  и ответственных, создание и утверждение. Нет дополнительного запроса состояния
  на каждую строку (N+1), нет выдуманного глобального количества.
- **Деталь проекта**: GET проекта/плана; GET состояния только при `statuses.read`.
  Прогресс, состояние и overdue не рассчитываются заново клиентом. Null прогресс
  отображается «Нет этапов». Этапы сортируются по position. Без права состояния
  сохраняется просмотр доступного плана с явным сообщением.
- **Материалы**: история только выбранного этапа, по 10 записей, версия,
  оригинальное имя, время, размер, решение и замечания. Авторизованная загрузка
  файла через fetch/Blob: JWT не в URL, имя очищается от разделителей/контрольных
  символов; object URL освобождается после передачи загрузки браузеру.
  Содержимое файла не вставляется в DOM; storage_key/внутренние пути не показываются.
- **Уведомления**: всем вошедшим пользователям, по 10 записей, фильтр непрочитанных.
  «Отметить прочитанным» использует существующий PATCH и перечитывает страницу.
  Нет автоматического прочтения при открытии, удаления или новых уведомлений.
- **Отчеты** (`reports.read`): сервер дополнительно требует свой teacher/department
  scope. Фильтры создания, student/supervisor/teacher ID, статус, overdue, limit
  1–100 и offset. Начало периода включительно, конец исключительно; текущее
  состояние, не история. Сводка относится ко всем matching до пагинации.
  Новые фильтры сбрасывают offset в 0; «Открыть смещение» использует последние
  примененные фильтры. Отдельно показываются отсутствие matching и пустая
  страница при высоком offset.

Администратор с начальными permissions видит уведомления, но не получает
академический глобальный доступ. Многоролевые пользователи сохраняют настоящие
права, переключатель фиктивной роли отсутствует.

Страницы проектов/материалов/уведомлений не имеют total в API. «Далее» доступно,
когда получено ровно limit строк; последняя полная страница может вести к пустой
следующей. Это ограничение текущего контракта. Reports использует total_matching.

## UTC и безопасность

Все отображаемые даты явно в UTC, null — «—».
`datetime-local` отчета помечен UTC: строка дополняется временем секунд и `Z`
до отправки, не трактуется как местное время компьютера.
Идентификаторы фильтров сохраняются как строки, с ограничением bigint.

Данные API вставляются textContent/безопасными DOM-узлами; нет innerHTML, eval,
исполнения содержимого, выдуманных статистик/записей или внешних URL из данных.
Кнопки имеют русские подписи, формы labels, таблицы th/caption и отдельный
горизонтально прокручиваемый регион. Есть фокус клавиатуры, ссылка пропуска
навигации, состояния загрузки/пустых данных/ошибок и адаптация узкого экрана.

Только ответы интерфейса имеют CSP: default-src none, локальные script/style,
connect-src self, frame-ancestors none, base-uri none и object-src none.
Без unsafe-inline, CORS, HSTS или изменения Swagger/авторизованных файлов.
Дополнительно no-store, nosniff и no-referrer. Это не заявление полной защиты
или production readiness.

## Воспроизводимые проверки

Зависимости выполнения не изменены. Только `requirements-test.txt` добавляет
Playwright 1.56.0 и закрепленные pyee 13.0.0/greenlet 3.3.0.
Chromium устанавливается отдельно (версия привязана к Playwright).
Зависимости ОС Linux устанавливаются `--with-deps` в CI.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m scripts.test_materials_unit
.\.venv\Scripts\python.exe -m pytest tests -v --postgres-backend=native --pg-bin="C:\Program Files\PostgreSQL\17\bin"
.\.venv\Scripts\python.exe -m pytest tests\test_web_ui_browser.py -v --postgres-backend=native --pg-bin="C:\Program Files\PostgreSQL\17\bin"
.\.venv\Scripts\python.exe -m pip check
git diff --check
```

Docker PostgreSQL остается режимом по умолчанию. См.
[README_tests_RU.md](./README_tests_RU.md). Fixtures создают собственный PostgreSQL,
случайные конфигурацию/пароли/JWT и временный uploads до импорта приложения;
настоящий `.env` не читается. HTTP fixture использует отдельный поток Uvicorn,
свой сокет на 127.0.0.1/случайном порту и выключенный lifespan (engine принадлежит
session fixture), проверяет ответ `/ui` и завершает только свой сервер.
Chromium, context и страницы созданы тестами и закрываются в finalization.
Чужой Uvicorn/браузер/аккаунты не используются.

API-тесты проверяют shell/resources, закрытость произвольных путей и прежние
root/health/docs. Отдельные браузерные проверки используют настоящий backend
для входа/доступа/отказов, данных, скачивания, report-фильтров, маркировки, смены
permissions/активности. Сеть контролируемо прерывается, поздняя доставка настоящего
ответа задерживается для проверки смены сессии. DOM-инъекции показываются текстом.
Также проверяются 360px, базовая клавиатура, отсутствие web storage/cookies.
Тесты имеют явные ожидания/timeouts и не пропускаются при отсутствии Chromium.

CI дополнительно устанавливает `python -m playwright install --with-deps chromium`
и выполняет весь `pytest tests`, включая браузер; рабочая БД/секреты не нужны.
Runner закреплен на `ubuntu-24.04`, поддерживаемой выбранной версией Playwright.
Переход `ubuntu-latest` на Ubuntu 26.04 не должен отключать браузерные проверки:
для обновления runner сначала нужна отдельная проверка совместимости.

## Ограничения и следующая версия

Создание/изменение проектов, планов/дат, загрузка/проверка материалов и
администрирование аккаунтов/ролей пока остаются в Swagger. Нет новых академических
API, frontend framework, локального кэша или общей версии состояния.
GET detail делает несколько запросов, поэтому при конкурентном изменении они
не образуют единый snapshot. Ошибка запроса показывает повтор раздела.
Не реализованы пользовательские настройки страницы, deep links, offline,
refresh/восстановление JWT, внешние уведомления или полный accessibility audit.
Проверен Chromium, не Firefox/WebKit, screen readers и все версии мобильных ОС.
Снимки экрана не включены. Сохраняются ограничения загрузок и атомарности
PostgreSQL/файловой системы. Не запускались генератор apply, scheduler, merge
или deployment. Эта версия — только доступ и просмотр, не весь интерфейс системы.
